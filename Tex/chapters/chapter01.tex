\section{Before You Build: The Failure Modes}
\label{sec:failure-modes}

\begin{learningbox}
After this section you will be able to name the six recurring
failure modes of production agent systems and map each one to a
missing interface contract.
\end{learningbox}

Production agent systems fail in a small, repeatable set of ways.
Understanding them \emph{before} writing a line of implementation
code is the most leverage a designer has.

\begin{itemize}
  \item \textbf{Unbounded loops.}  The agent re-enters
        \textsc{Planning} indefinitely because no cycle budget is
        enforced at the \emph{interface} level.
  \item \textbf{Silent cost overruns.}  Token and cost tracking
        are added as an afterthought, so
        \lstinline{ExecutionContext} carries no budget methods.
  \item \textbf{Untestable reasoning.}  The LLM call is
        hardwired into a monolith; the \lstinline{Reasoning}
        contract was never extracted, so unit tests are impossible
        without a live API.
  \item \textbf{Replay impossibility.}  No checkpoint interface
        exists; post-incident forensics require re-running with
        live side-effects.
  \item \textbf{Stagnation blindness.}  The state machine has no
        \lstinline{stagnantCycles} counter, so a stuck agent
        appears ``busy'' to operators until cost limits fire.
  \item \textbf{Tenant bleed.}  A static thread pool is shared
        across tenants; one high-volume tenant starves every
        other run.
\end{itemize}

\begin{notebox}
Every failure mode above is detectable---and preventable---at the
interface-design stage.  The chapters that follow show \emph{how}
this framework encodes each guard as a method signature, not as
runtime glue.
\end{notebox}

\section{Runtime Requirements}
\label{sec:runtime-requirements}

\begin{learningbox}
After this section you will be able to state the five
non-negotiable runtime properties and identify which constructor
argument of \lstinline{AgentRuntime} enforces each one.
\end{learningbox}

A production agent runtime must satisfy five non-negotiable
properties \emph{before} any feature is built on top of it.

\begin{enumerate}
  \item \textbf{Bounded execution} --- every run has a hard cycle
        limit and token budget enforced by the context, not by
        convention.
  \item \textbf{Deterministic replay} --- a serialisable
        \lstinline{Snapshot}\marginpar{\footnotesize Vol.~1, Ch.~8}
        can recreate any past run without side-effects.
  \item \textbf{Tenant isolation} --- the async thread pool is
        \emph{instance-scoped}, not static, so per-tenant
        executors can be injected.
  \item \textbf{Observable lifecycle} --- every state transition
        emits a typed event through \lstinline{EventSink} before
        any handler runs.
  \item \textbf{Suspension / resumption} --- the state machine
        can park at \lstinline{SUSPENDED\_HITL} and be cleanly
        restarted from a persisted snapshot.
\end{enumerate}

\lstinline{AgentRuntime} (Listing~\ref{lst:agentruntime}) encodes
all five requirements directly in its constructor signatures.

\begin{lstlisting}[
  language=Java,
  caption={AgentRuntime --- three constructors enforce tenant
           isolation and observability
           (\texttt{core/AgentRuntime.java})},
  label={lst:agentruntime}]
public AgentRuntime(PlanValidator validator) {
    this(validator, EventSink.noop());
}

public AgentRuntime(PlanValidator validator, EventSink events) {
    this(validator, events, Executors.newCachedThreadPool(r -> {
        Thread t = new Thread(r, "agent-async");
        t.setDaemon(true);
        return t;
    }));
}

/**
 * Primary constructor --- accepts a caller-supplied executor
 * for tenant isolation.
 */
public AgentRuntime(PlanValidator validator, EventSink events,
                    ExecutorService asyncPool) {
    this.validator = validator;
    this.events    = events;
    this.asyncPool = asyncPool;
}
\end{lstlisting}
\githubref{com.agentframework.core.AgentRuntime}

\begin{notebox}
\lstinline{EventSink.noop()} lets unit tests instantiate
\lstinline{AgentRuntime} with a single argument and zero
infrastructure.  Production code injects a real sink at the
outermost wiring layer.
\end{notebox}

\section{Testability and Observability}
\label{sec:testability-observability}

\begin{learningbox}

\end{learningbox}

Six principles shape every interface in this framework.
Table~\ref{tbl:six-principles} lists them with the contract that
enforces each one.

\begin{table}[htbp]
\centering

  \textbf{Interface / type} \\

\section{Java Concurrency Models}
\label{sec:concurrency-models}

\begin{learningbox}
After this section you will be able to describe the synchronous
and async execution paths and explain why the runtime never owns
scheduling policy.
\end{learningbox}

\lstinline{AgentRuntime} exposes both a synchronous path and a
\lstinline{CompletableFuture}-based async path
(Listing~\ref{lst:async}).

\begin{lstlisting}[
  language=Java,
  caption={Async execution --- result delivered via
           CompletableFuture (\texttt{core/AgentRuntime.java})},
  label={lst:async}]
public CompletableFuture<ExecutionResult> executeAsync(
        Agent agent, Task task) {
    return CompletableFuture.supplyAsync(
        () -> execute(agent, task), asyncPool);
}

public CompletableFuture<ExecutionResult> executeAsync(
        Agent agent, Task task,
        String tenantId, String userId) {
    return CompletableFuture.supplyAsync(
        () -> execute(agent, task, tenantId, userId), asyncPool);
}
\end{lstlisting}
\githubref{com.agentframework.core.AgentRuntime}

The runtime never decides scheduling policy --- it only
\emph{respects} the pool it receives.  Inject a bounded,
named pool per tenant; never share one across tenants.

\begin{warningbox}
Never share a single \lstinline{ExecutorService} across tenants.
One tenant submitting thousands of short tasks will starve all
others.  Use the three-argument constructor and inject a bounded
pool per tenant.
\end{warningbox}

\subsection{The \texttt{Agent} Composite}
\label{subsec:agent-composite}

\lstinline{Agent} (Listing~\ref{lst:agent}) is a pure value
object.  It holds \emph{no mutable state}; all state lives in
\lstinline{ExecutionContext}\marginpar{\footnotesize Vol.~1, Ch.~4}.

\begin{lstlisting}[
  language=Java,
  caption={Agent --- validated composite of four interface slots
           (\texttt{core/Agent.java})},
  label={lst:agent}]
public final class Agent {
    private final String     name;
    private final Perception perception;
    private final Reasoning  reasoning;
    private final Action     action;
    private final Memory     memory;

    private Agent(Builder b) {
        name=b.name; perception=b.perception;
        reasoning=b.reasoning;
        action=b.action; memory=b.memory;
    }
    public static class Builder {
        public Agent build() {
            Objects.requireNonNull(perception, "perception");
            Objects.requireNonNull(reasoning,  "reasoning");
            Objects.requireNonNull(action,     "action");
            Objects.requireNonNull(memory,     "memory");
            return new Agent(this);
        }
    }
}
\end{lstlisting}

\subsection{Tenant Policy Engine}
\label{subsec:tenant-policy}

\begin{lstlisting}[
  language=Java,
  caption={TenantPolicy --- immutable per-tenant rule set
           (\texttt{security/TenantPolicy.java})},
  label={lst:tenantpolicy}]
public record TenantPolicy(
        String tenantId,
        Set<String> allowedTools,
        int maxCyclesPerRun,
        int maxTokensPerRun,
        boolean allowIrreversible) {

    public static TenantPolicy permissive(String tenantId) {
        return new TenantPolicy(tenantId, Set.of(),
            Integer.MAX_VALUE, Integer.MAX_VALUE, true);
    }
    public static TenantPolicy restricted(
            String tenantId, Set<String> tools) {
        return new TenantPolicy(tenantId, tools, 20, 50_000, false);
    }
    public boolean toolAllowed(String toolName) {
        return allowedTools.isEmpty()
            || allowedTools.contains(toolName);
    }
}
\end{lstlisting}
\githubref{com.agentframework.security.TenantPolicy}

\begin{lstlisting}[
  language=Java,
  caption={TenantPolicyEngine.check() --- switch on sealed
           Decision (\texttt{security/TenantPolicyEngine.java})},
  label={lst:policyengine}]
public ValidationVerdict check(
        String tenantId, Decision decision) {
    TenantPolicy p = get(tenantId);
    return switch (decision) {
        case ToolCall tc -> {
            if (!p.toolAllowed(tc.toolName()))
                yield ValidationVerdict.failed(
                    "Tool not allowed: " + tc.toolName());
            yield ValidationVerdict.ok();
        }
        case ParallelToolCalls ptc -> {
            for (ToolCall tc : ptc.calls())
                if (!p.toolAllowed(tc.toolName()))
                    yield ValidationVerdict.failed(
                        "Parallel tool not allowed: "
                        + tc.toolName());
            yield ValidationVerdict.ok();
        }
        default -> ValidationVerdict.ok();
    };
}
\end{lstlisting}
\githubref{com.agentframework.security.TenantPolicyEngine}

\section{A Run from First Call to Final State}
\label{sec:run-walkthrough}

\begin{learningbox}
After this section you will be able to trace a single run
through every state transition from \lstinline{INITIALIZED} to a
terminal state using only the interface contracts defined above.
\end{learningbox}

With all contracts in place, the run loop is a straightforward
orchestration.  Listing~\ref{lst:smr-planning} shows the
\lstinline{PLANNING} step from
\lstinline{StateMachineRunner.step()}.

\begin{lstlisting}[
  language=Java,
  caption={StateMachineRunner --- PLANNING step orchestration
           (\texttt{core/StateMachineRunner.java})},
  label={lst:smr-planning}]
case PLANNING -> {
    emit(ctx, AgentEvent.EventType.CYCLE_STARTED,
        Map.of("cycle", ctx.cycleCount()));

    Observations obs = agent.perception().perceive(ctx);
    ctx.transitionTo(RunState.MODEL_CALL);
    Decision decision = agent.reasoning().decide(ctx, obs);
    ctx.transitionTo(RunState.PLANNING);

    ValidationResult validation =
        validator.validate(decision, ctx);
    switch (validation) {
        case ValidationResult.Passed p -> {
            ctx.transitionTo(RunState.TOOL_EXECUTION);
            ActionResult result =
                agent.action().execute(decision, ctx);
            ctx.transitionTo(RunState.MEMORY_UPDATE);
            new Review(validator, events, taintClassifier)
                .step(result, decision, obs, ctx, agent);
            ctx.recordCycle(CycleRecord.of(
                ctx.cycleCount(), obs, decision,
                result, "ok"));
            ctx.incrementCycle();
            if (!ctx.currentState().isTerminal())
                ctx.transitionTo(RunState.VALIDATING);
        }
        case ValidationResult.NeedsCorrection nc -> {
            ctx.incrementRevisionCount();
            ctx.flagPlanStale(nc.reason());
            ctx.transitionTo(RunState.VALIDATING);
        }
        case ValidationResult.Failed f ->
            terminate(ctx,
                new TerminationReason.PlanIncoherent(
                    f.reason()),
                AgentEvent.EventType.PLAN_STALE,
                Map.of("reason", f.reason()));
    }
}
\end{lstlisting}
\githubref{com.agentframework.core.StateMachineRunner}

\begin{notebox}
\lstinline{DEGRADED} always transitions to \lstinline{ABORTED},
never to \lstinline{TERMINATED} (C4 spec fix, Vol.~1, Ch.~8).
\end{notebox}

\begin{takeawaybox}{Chapter 1 Takeaways}
Every failure mode in production agent systems maps to a missing
interface contract: bounded execution, deterministic replay,
tenant isolation, observability, and suspension are all encoded in
constructor signatures, not left to convention.
Four single-method interfaces---\lstinline{Reasoning},
\lstinline{Action}, \lstinline{Memory}, \lstinline{Perception}---make
every behaviour unit-testable with a lambda and eliminate the
need for a live model or infrastructure in any unit test.
\end{takeawaybox}
